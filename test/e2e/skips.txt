# Tests silenced in every profile, including the full one a release gates on.

# One Ginkgo skip regex per line, matched against the whole test name. Blank
# lines and # comments are stripped; the runner joins what is left with "|" and
# passes it as --ginkgo.skip. Every line needs a comment saying why, and a line
# that stops being true should be deleted rather than left behind.
#
# This file is only one of the three ways a test goes unrun. The other two are
# capability flags in testdriver.yaml and options left unset there; testing.md
# has the full table of what is silenced and by which mechanism.

# Node and kubelet failover: kills or restarts the kubelet under a running pod
# and checks the volume is cleaned up and reusable afterwards. Deliberately
# deferred — this is the failure class the project has not built for yet, and
# testing it properly means killing a Hyper-V VM rather than a kubelet, which
# the upstream suite cannot orchestrate. These also require SSH to the nodes,
# which --provider=skeleton does not have, so they would error rather than fail
# honestly. See "Node failover" in testing.md for the plan to cover this with
# our own tests.
\[Disruptive\]

# Everything behind a Kubernetes feature gate or an environment this cluster is
# not. Upstream's own README recommends skipping the whole [Feature: family,
# and this was that one-prefix skip until CreateSnapshot landed. It is now an
# enumeration of the family minus one branch, because
# [Feature:VolumeSnapshotDataSource] is the one this driver can finally be held
# to. Each alternative is still a prefix, not a whole tag, so it catches the
# longer real tag names too — [Feature:SELinuxMountReadWriteOncePod] and the
# like. What stays hidden, in descending order of count:
#   [Feature:Windows]                 — Windows worker nodes. Ours are Linux.
#   [Feature:VolumeAttributesClass]   — mutable volume attributes. Not implemented.
#   [Feature:VolumeSourceXFS]         — xfs. The node image has only e2fsprogs.
#   [Feature:SELinux]                 — SELinux mount options. Not implemented.
#   [Feature:volumegroupsnapshot]     — group snapshots. Not implemented; also
#                                       off via the groupSnapshot capability.
#   [Feature:snapshotmetadata]        — snapshot metadata. Not implemented.
#   [Feature:OffByDefault]            — gates disabled on a default cluster.
#
# What is deliberately no longer hidden is [Feature:VolumeSnapshotDataSource]:
# CreateSnapshot, DeleteSnapshot and ListSnapshots are implemented and
# snapshotDataSource is true in testdriver.yaml, so these are the tests that
# exercise them. They need three things on the cluster or they fail rather than
# skip — the snapshot.storage.k8s.io CRDs, the cluster-wide snapshot-controller,
# and the chart's own external-snapshotter sidecar
# (controller.snapshotter.enabled, off by default).
#
# Enumerating rather than matching the whole family costs one thing: a feature
# tag upstream adds later now runs instead of being silenced. That is the right
# way round — a new tag deserves a look — but it ties this list to the e2e.test
# version, so reread it when that moves.
\[Feature:(Windows|VolumeAttributesClass|VolumeSourceXFS|SELinux|volumegroupsnapshot|snapshotmetadata|OffByDefault)
